# Architecture decisions

## Runtime contracts

- Plugin metadata and install lifecycle follow the GLPI plugin structure: `setup.php` supplies `plugin_init_*`, version and prerequisite functions; `hook.php` supplies install/uninstall functions. GLPI's plugin manager installs, activates, updates and uninstalls the plugin. Uninstall removes the plugin-owned configuration context; it does not delete plugin source.
- The supported version range is GLPI `>=11.0.0,<11.1.0`. Plugin controllers are discovered from `src/Controller`, use PSR-4 `GlpiPlugin\Bookstackbridge\Controller`, extend `Glpi\Controller\AbstractController`, use Symfony `Route` attributes and return Symfony responses. Twig templates are addressed using `@bookstackbridge/...`.
- GLPI versions before 11.0.7 have a plugin route method-matching bug. Form routes advertise `GET` and `POST` for discovery compatibility, then explicitly reject non-POST requests in the controller; this does not permit state changes by GET.
- In GLPI 11.0.4, `TemplateRenderer` constructs `RoutingExtension` without a router. The plugin routes live in the separate plugin router, so Twig `path()` cannot resolve their names and falls back to `Html::getPrefixedUrl()`. Use `path('/plugins/<plugin-key>/<route>')` for plugin form actions; `Html::getPrefixedUrl()` prepends GLPI's `root_doc`, preserving installations below a URL subdirectory. This project uses `/plugins/bookstackbridge/`; do not use `Plugin::getWebDir()`, which GLPI deprecates.
- Navigation is registered with the documented `menu_toadd` hook. The menu and every knowledge route require GLPI's native `knowbase` `READ` right. Configuration, API test, and search routes independently require `config` `UPDATE`; hiding a menu is never treated as authorization. GLPI 11.0.4 defines the Knowledge base profile right separately and marks General setup (`config`) as having no read right.
- The `csrf_compliant` hook opts the plugin into GLPI's CSRF validation. Mutating and query forms carry GLPI's `_glpi_csrf_token` Twig token field.
- `secured_configs` declares `api_token` in the `plugin:bookstackbridge` context. GLPI's `Config::setConfigurationValues()` encrypts this value and includes it in security-key migration, while `Config::getConfigurationValues()` returns the stored ciphertext. `ConfigRepository` decrypts the secret once with GLPI's `GLPIKey` before backend use or credential merging; writes always pass plaintext to GLPI for encryption. The Token ID is not encrypted. Decryption errors are converted to a safe instruction to enter the secret again, and credential fields are cleared before rendering. The plugin does not recursively decrypt or detect layered ciphertext: secrets affected by earlier partial saves must be entered again once after updating.

## BookStack API

BookStack's API routes are rooted at `/api`, so the configured URL should be the BookStack site origin or installation path prefix, without an `/api` suffix. The client appends `/api/search`, `/api/shelves`, `/api/shelves/{id}`, and `/api/books/{id}`. Shelf listings use the list API's `count` and `offset` parameters. Shelf detail exposes its books; book detail exposes a structural `contents` tree with chapters, nested pages, and pages directly under the book. The navigation service whitelists IDs, names, and plain descriptions and discards API URLs and page body fields. It does not call page read endpoints or render BookStack HTML.

BookStack's official API uses `Authorization: Token <id>:<secret>`. Standard list endpoints contain `data` and `total`, accept `count` (default 100, maximum 500) and `offset`, and report errors with 4xx/5xx status codes. Global search is `GET /api/search` with required `query`, `page` (minimum 1) and `count` (maximum 100); this plugin requests 20 results per page. Connectivity is tested with a one-item `GET /api/shelves` list request. Responses remain scoped to the BookStack token owner's roles and content permissions.

The HTTP client is read-only, verifies TLS, does not follow redirects, disables proxy use, limits connect/total time, and accepts only HTTPS on the standard port. URL policy rejects credentials, query/fragment, local names, malformed hostnames, unsafe paths, loopback, link-local, metadata, multicast, and reserved IPs. Private RFC1918/ULA IPs are rejected unless each exact private IP is explicitly present in the administrator-managed `allowed_private_ips` configuration; CIDR ranges and hostnames are not accepted in that allowlist. DNS A and AAAA results are all validated and the chosen address is pinned to the hostname and port with cURL `CURLOPT_RESOLVE` for the request, preserving hostname-based TLS/SAN verification and preventing a DNS change between policy validation and connect. The API token is never written to logs or rendered into HTML.

Private destination authorization does not alter the TLS trust store or bypass certificate/SAN checks. The plugin currently relies on the PHP/cURL runtime's trusted CA configuration and has no per-plugin CA bundle option. See [network-configuration.md](network-configuration.md) for the allowlist, trust-store, firewall, and diagnostic procedures.

## M1.1 structural navigation

The GLPI menu opens the read-only knowledge routes for users with the native `knowbase` `READ` right. Each route checks that right independently. Requests use the same protected credentials and BookStack client policies as M0. The configured integration account's BookStack role and content permissions are shared by all GLPI readers; operators must only grant this GLPI right to profiles authorized for the account's content scope. The UI uses the GLPI 11 Twig page layout and prefixed resource paths. Shelf results paginate in batches of 100; the official shelf and book detail responses embed their related books/pages rather than exposing separately paginated relation collections. A selected page currently shows only its title and a note that full reading is deferred to M1.2. No BookStack content is persisted in GLPI.

## Scope

No BookStack database access or core modifications are used. GLPI Migration is used only to install the plugin-owned entity connection table; no JavaScript framework or third-party runtime library is added. Controllers, API client, navigation service, security policy, and menu implement current M0/M1.1 behavior. Future ticket associations and selective GLPI knowledge-base sync remain out of scope.

## E1 entity connection storage (in progress)

The E1 foundation introduces `glpi_plugin_bookstackbridge_connections`, with a unique row per numeric GLPI entity ID. The row stores connection URL and exact private-IP allowlist alongside separately protected Token ID and Token Secret. Both credential columns are encrypted and registered through GLPI 11's `secured_fields` hook so GLPI's `glpi:security:changekey` command can rotate them. Empty credentials are stored as `NULL`, because GLPI's rotation processes every non-NULL field and would otherwise encrypt empty strings. The existing global `plugin:bookstackbridge` configuration and its `secured_configs` declaration remain intact as a recovery source; installation does not copy them to an entity.

`EntityConnectionRepository` reads and writes entity rows using GLPI's `GLPIKey` mechanism. Partial updates decrypt stored credentials once and pass plaintext only to `GLPIKey::encrypt()` before persistence; unreadable values cannot be used and can only be replaced by submitting a replacement for that credential. `copyLegacyConfigurationToEntity()` requires an exact entity-bound confirmation string and an explicit backup confirmation, copies to one entity only, refuses an existing destination, and retains the global source. It is a backend primitive for a later administrator workflow, not an automatic migration or user-facing feature in E1.

This E1 storage layer is not yet wired into controllers or the M1.1 catalog. Do not treat it as multi-entity runtime authorization. Uninstall follows GLPI's plugin database convention and removes the plugin-owned table and legacy config; back up the GLPI database and `glpicrypt.key` before uninstalling. Entity repository tests use a fake GLPI database and fake GLPIKey; actual schema installation and security-key rotation still require a GLPI 11.0.4 environment.
